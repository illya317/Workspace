# Platform Governance Route Shell

- `/settings/governance` is the single Settings L2 for non-routine platform governance.
- `page.tsx` authenticates through `requireRouteAccess("/settings/governance")` and mounts `SettingsGovernancePage` from `@workspace/settings`.
- UI declarations, database relations, SQL settings, module management/source analysis, and operations records are same-page tabs; tab changes remain client state.
- The retired `/settings/ui` route and `settings.ui` resource are not compatibility aliases.
- Database-schema reads, relation-policy reads/writes, and module-management reads/writes use `/api/settings/governance/**`; all remain root-only in their route handlers, and writes require `settings.governance.configure` through the registry-derived API policy. 数据关系中的 `关系规则` 按模块展示完整 Relation Catalog 和未登记的物理外键，只开放两类有真实消费者的业务设置：删除联动 `targetDelete`，以及显式登记的业务必填 `businessRequired`。共享 adapterKey 原子保存并保留版本、理由和修订历史；启用业务必填前必须预检现有空值，预检与 CAS 保存处于同一加锁事务。物理 FK、列可空性、约束和数据库 `onDelete` 永远只读，`数据库证据`常驻展开，保存不执行 DDL。非空退役或旧隐藏字段配置只允许显式 reset，运行时在清理前 fail closed。
- SQL-settings GET/PATCH use `/api/settings/governance/sql-settings` and remain root-only; PATCH additionally resolves to `settings.governance.configure`. The `3:7` workspace exposes an allowlisted live catalog, three guarded runtime timeout changes, and a runtime-password rotation request. Writes only enqueue bounded, idempotent operations with expected-current evidence; a separate host worker performs privileged SQL and secret rotation. The web runtime never receives generated credentials or database administration privileges, while TLS, HBA, server logging, WAL, listener, and backup changes remain host-operation-only.
- Operations Records v1 is an explicit empty state. Production receipt files and local NDJSON are not read directly by the UI; later providers must add a server DTO and permission-scoped API under this L2.
